# First launch and the ROM conversion

The game ships no game data: the player supplies the ROM, and the first launch turns it into the
PC-layout files the engine loads. Read this when a first launch fails or a converter changes.

## Where the ROM goes

In the data folder (`$S/`: `data/` next to the executable, `sdmc:/switch/project-dam/data/` on
the Switch), named after its region:

| Region | Accepted names |
|---|---|
| US (NTSC) | `ge007.ntsc-final.z64`, `baserom.u.z64` |
| Europe (PAL) | `ge007.pal-final.z64`, `baserom.e.z64` |
| Japan | `ge007.jpn-final.z64`, `baserom.j.z64` |

The ROM must be an unmodified retail dump in big-endian `.z64` order. The region comes from the
country byte of the header (`0x3E`).

## The conversion

Two "sidecar" trees are derived from the ROM:

- `$S/pcmodels-<region>/` (`pcmodels.bin` + `manifest.csv`): models, read by `port/src/pcmodels.c`.
- `$S/pccg-<region>/` (`pccg.bin` + `manifest.csv`): stage data, read by `port/src/pccg.c`.

At boot `romdataInit()` calls `romConvertEnsureSidecars()` (`port/src/romconvert.c`). If both
`.bin` files exist it does nothing. Otherwise it runs the converter in the game's own process,
writes the trees into `data/`, and checks again. It takes a few seconds and runs once.

The models tree also holds `converter.ver` (`CV_CONVERTER_VERSION` in `port/convert/convert.h`;
a missing file counts as 1). When it differs from the running converter's, boot converts the whole
ROM again, once (version 4 changed the setup files, so not only the models). Bump the version
whenever a converter change alters its output ([model-subdivision.md](model-subdivision.md)).

After the sidecars, the same call makes sure the game's base asset pack exists:
`$S/../assetpacks/ge007.passets`, an uncompressed tar holding the textures, levels, models,
characters, labels, music and sounds exported from the ROM (layout: `docs/specs/asset-packs.md`,
"The base pack layout"). When its `pack.json` is missing or its `exporter_version` differs from
the running exporter's (`EX_EXPORTER_VERSION`, `port/export/export.h`),
`ex_ensure_base_asset_pack()` (`port/export/pack_export.c`) builds it in `ge007.passets.tmp/`,
packs it and renames it into place, so a killed run leaves no half pack. It takes a few seconds
(about 7 on a desktop PC) and runs once per exporter version. A pack written for the first time
is enabled, last in `Video.AssetPacks`; the older `texturepacks/ge007.ptexpack` is then removed.
`ge007-export` and `--export-levels` write the same pack.

If the files still cannot be produced, boot stops with a message asking for a retail `.z64` ROM.
That is deliberate: a missing sidecar would otherwise crash much later, in model loading.

## The boot screen

The game's own window does not exist yet at that point, so `port/src/bootscreen.c` (#64) shows a
small screen of its own: one 640×360 software canvas, in an SDL window of the game's size on the
PC (`videoBootWindowGeometry()`) and on the libnx framebuffer on the Switch. It is closed before
`videoInit()` and never touches the game's renderer.

- **Converting:** "PROJECT DAM" and a progress bar in three equal parts (models, stage
  backgrounds, stage setups), fed by the converter's progress callback (`cv_set_progress`). At
  the end it waits for A (a key or a click on the PC).
- **Textures:** the same screen with the label "Textures" and a bar of its own, fed by
  `ex_set_progress` while the base asset pack's textures are written. It closes without waiting
  for a key.
- **ROM not found** (`romdata.c`): the expected file name and the folder to copy it to. A ROM
  that was found but refused gets the reason instead.
- **Conversion failed** (`romconvert.c`): asks for an unmodified retail `.z64`; the log has the
  details. A base asset pack that cannot be written (folder not writable, no space) stops boot
  the same way ("Asset pack not written"): the game reads its assets from the packs. When a
  rewrite after an exporter update fails but the older pack is still there, boot goes on with it.

Messages wait for a press, then the game quits. Every message also goes to the log. On the PC,
when no window can be opened, a native message box shows it instead. The text uses an embedded
8×16 bitmap font (`bootfont.h`, generated by `tools_pc/gen_bootfont.py`, declared in `NOTICE`).

## The converter

`port/convert/` is a C port of the old Python converters (#61), freestanding (libc + zlib, no decomp
headers) so the same code links into the game and into a command-line tool:

- `conv_d43.c` models, `conv_d69.c` stage backgrounds, `conv_d88.c` stage setups and prop
  definitions; `cv_convert_rom()` in `conv_main.c` runs them.
- The decomp metadata the converters need is embedded in `convert_data.c`, generated by
  `tools_pc/gen_convert_data.py`. Regenerate it; do not edit it.
- The output was byte-identical to the Python scripts on all three regions when they were
  removed: compare against a known-good conversion after any converter change.

The CLI (built off the Switch):

```sh
ge007-convert --rom ROM.z64 [--out DIR] [--region ntsc-final|pal-final|jpn-final] [--only d43|d69|d88]...
```

It writes `DIR/data/pcmodels-<region>/` and `DIR/data/pccg-<region>/`.

## Switch SD layout

`tools/switch/make_sd.sh <rom.z64> [out_dir]` (in the build container, after the Switch build)
stages `switch/project-dam/project-dam.nro` and the ROM copy under `data/`. No sidecars are
staged: the console converts on first launch, like every other platform.
